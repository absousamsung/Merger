# DECISIONS.md — Phase 2 (MCP Media Generator)

Format: decision — reason (alternative rejected). Reality deviations from the master spec are flagged with **DEVIATION**.

1. **DEVIATION — Node transport replaced by `WebStandardStreamableHTTPServerTransport`**: SDK 1.32's Node `StreamableHTTPServerTransport` is now a thin wrapper (`@hono/node-server`) around the web-standard transport, which consumes a `Request` and returns a `Response` directly — a perfect fit for App Router route handlers. A hand-written Node req/res bridge was built first and removed after discovering this (rejected: bridge — redundant, and hono's conversion broke on synthetic streams).
2. Stateless `/mcp`: fresh `McpServer` + `WebStandardStreamableHTTPServerTransport({ sessionIdGenerator: undefined })` per request, all state in Turso — no session affinity needed across serverless instances (spec 4/7). Verified across separate curl requests.
3. Transport teardown deferred until the response body stream ends (`pipeThrough(TransformStream{flush})`) — the transport resolves its `Promise<Response>` before the SSE stream drains, so eager close truncated in-flight results (observed live, then fixed).
4. **DEVIATION — Progress notifications best-effort**: sent via `extra.sendNotification({ method: "notifications/progress", ... })` when the client supplies `_meta.progressToken`; polling via `get_task` always works regardless. Ordering across hono-free SSE streams could not be asserted deterministically, so correctness never depends on them (spec allows best-effort for in-memory-only optimizations; client instructions mandate polling).
5. **DEVIATION — Timestamps as JS ISO strings**: the spec schema uses SQLite `datetime('now')` defaults, but lease/cooldown comparisons (`lock_until < now`, `next_retry_at`) must be lexicographically consistent with ISO strings; mixing formats breaks comparisons. All timestamps written from JS (`new Date().toISOString()`).
6. Extra columns on `api_keys`: `key_mask` + `key_fp` (sha256) — masking and duplicate checks are computed from plaintext at insert time, so they never depend on `ENCRYPTION_KEY` being present at read time. Encryption is AES-256-GCM (`enc1:iv:tag:ct`) with graceful fallback to plaintext when the key is absent; re-adding a key encrypts it.
7. Key pool strictly `ORDER BY created_at ASC, id ASC`; `exhausted` keys remain in rotation and self-recover to `active` on first success (verified live: exhausted key completed a task and flipped back).
8. Failover semantics for mid-task key death: the provider_task_id is NEVER blindly recreated (idempotency, avoids double-paid jobs); instead the same provider task is re-checked with other keys of the same provider. Recreation happens only when no provider job exists yet.
9. "All keys failed at creation" keeps the task `processing` with `next_retry_at = now+45s`; every `get_task` retries after cooldown; the safety valve fails it with the generic Arabic message after `STUCK_TASK_MAX_MINUTES` (verified live by backdating `created_at`).
10. Sanitization: `sanitizeForClient` maps key/balance/internal markers (including `stuck`, `STUCK_TASK`, `all keys failed`) to "الخدمة غير متاحة مؤقتًا، حاول لاحقًا" — the client never sees key/balance errors (verified live).
11. **DEVIATION — merge_videos validation messages carried on the zod schema**: the SDK's zod input validation rejects 1/11-clip inputs before the handler runs, so the spec's exact Arabic messages are attached to `.min(2, msg).max(10, msg)` — schema still publishes minItems/maxItems per spec 7.2 while clients receive the exact Arabic text (verified live).
12. kie.ai shapes verified with REAL calls on 2026-11-11: `createTask {model, input}` → `{code:200,data:{taskId}}`; `recordInfo` → `data.state` + `resultJson` (a JSON **string**, parsed twice) + `response.resultUrls` fallback; image gen ≈20 s / ~7.8 credits. Non-200 body `code` treated as error even on HTTP 200.
13. CometAPI adapter implemented per documented shapes (OpenAI-compatible images sync endpoint + async video tasks); **untested end-to-end — no CometAPI key was available**; b64_json-only image output is classified as `provider` (fail over) because we must not host binaries.
14. Merge orchestration: `process` fired exactly once via DB lease (20 s) + attempts journal + in-memory set; merge service's own atomic claim (`202` on re-run) is the second safety layer; 404 on status → final failure with the exact Arabic retention message.
15. Admin auth: HMAC-signed httpOnly SameSite=Lax cookie (7 d) from `ADMIN_PASSWORD` (+`ENCRYPTION_KEY` in the HMAC); constant-time compares everywhere; `/api/health` stays public and exposes booleans only; `/mcp` guarded by its own `MCP_ACCESS_TOKEN` when set.
16. Connection card never exposes `MCP_ACCESS_TOKEN` — configs render `Bearer <ضع القيمة من متغيرات البيئة>` placeholder (admin already knows it; no secret leaves the server).
17. **DEVIATION — sandbox-only instrumentation**: `src/instrumentation.ts` (gated by `MERGER_AUTO_START=1`) auto-spawns a local instance of the Phase 1 dev server so the live sandbox preview keeps the merge feature working; it is a no-op in production deploys where the flag is unset and `MERGER_API_BASE` points at the deployed Phase 1.
18. `MERGER_PUBLIC_BASE` (optional): lets result links use a different public host than the internal `MERGER_API_BASE` (useful behind proxies/gateways); defaults to `MERGER_API_BASE`.
19. Dashboard uses shadcn/ui + system Arabic font stack (no Google Fonts network dependency at build time), full RTL (`dir="rtl"`), task board auto-refreshes every 5 s, keys every 8 s, health every 10 s.
20. Adaptive `wait_seconds` capped at 240 s inside the handler and `maxDuration = 300` on `/mcp` — keeps the wait window safely under the serverless ceiling (spec 7.3.5).
21. Unknown tool calls return the spec's exact Arabic message ("❌ أداة غير معروفة… المتاح: …") — intercepted in the route before the transport, delivered as an `isError` tool result (verified live).
22. Model aliases normalized via dot-normalization (`gpt-image-2.6/...` → `gpt-image-2-6/...`); env overrides `KIE_IMAGE_MODEL` etc. change only the provider-side model id, keeping the canonical task identity stable.
